# 车研：购车资料检索与车型比较助手

车研面向中国市场的购车研究场景，提供精确到车型、年款和配置版本的比较，以及基于官方用户手册的资料问答。系统将官网配置目录与可检索原文关联，展示价格、配置、资料出处和手册页码，帮助用户核对购车信息。

## 能做什么

- 搜索车型，从 10 款比亚迪 2026 款车型中选择具体配置版本。
- 并列比较 2 至 3 个版本的官方指导价、能源指标、轮胎及部分装备，展示官网来源与采集日期。
- 按所选车型检索用户手册和品牌售后服务流程，返回原文、来源链接及 PDF 页码。
- 根据检索原文回答问题，并在展示前核对模型选出的引文。
- 从指定手册页抽取故障信号、风险、建议操作、保养周期和配置说明等结构化事实。
- 上传并索引 PDF、HTML、Markdown 和纯文本资料，填写来源并关联车型。
- 在生成服务异常时展示检索原文，并标明当前回答模式。

## 设计取舍

1. **结构化数据与检索增强生成分离。** 指导价、价格差值和标准能耗由带来源的配置目录提供并由程序计算；模型负责解释检索到的原文。购车比较对数值和出处的准确性要求高，这种分工便于逐项核验。
2. **引文由程序校验。** 模型选出相关句子后，程序回到候选片段核对原文，匹配成功才展示引文。展示条件由代码执行，独立于提示词对模型的约束。
3. **使用 SQLite 与 NumPy 检索。** 当前默认索引含 1237 个片段，逐条计算余弦相似度便于检查切分、过滤和排序结果。资料增长到十万级片段时，可替换为专用向量索引。
4. **对缺少统计来源的指标明确拒答。** 车主满意度、车型故障率和实际成交均价需要独立调查或交易数据。现有资料没有这些来源，系统直接说明资料不足。
5. **三段式回答状态。** 引文核验成功时返回 `evidence_selected`；检索或引文核验未得到证据时返回 `no_evidence`；生成服务或解析失败时返回 `retrieval_only` 并展示检索原文。用户可以从状态区分已核验引文、资料不足与生成失败。

## 快速开始

在项目根目录使用 Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
ollama pull quentinz/bge-small-zh-v1.5
ollama pull qwen2.5:3b
.\.venv\Scripts\python.exe -m carwise.fetch_sources
.\.venv\Scripts\python.exe -m carwise.ingest
.\.venv\Scripts\python.exe -m uvicorn carwise.main:app --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765/`。第一个 Ollama 模型生成中文文本向量，第二个模型组织资料问答。车型比较使用本地配置目录。使用 DeepSeek 生成回答时，在启动服务前设置 `CARWISE_LLM_PROVIDER=deepseek` 和 `CARWISE_DEEPSEEK_API_KEY`；文本向量仍由本地 Ollama 提供。

```powershell

.\.venv\Scripts\python.exe -m carwise.sync_byd --with-features
```

脚本通过 Microsoft Edge 读取官网参数页，校验返回的车型名称，并记录采集日期。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /api/vehicles` | 查询车型和配置版本 |
| `GET /api/documents` | 查询资料及索引片段数 |
| `POST /api/documents` | 上传资料并关联车型 |
| `POST /api/compare` | 比较配置版本 |
| `POST /api/search` | 查看原文检索结果 |
| `POST /api/ask` | 返回经过引文核验的回答与状态 |
| `POST /api/extract` | 抽取指定页的结构化事实 |
| `GET /api/health` | 查询车型数与索引片段数 |
| `GET /docs` | 查看交互式接口文档 |

## 参数选择

`tools/ablate_chunk_size.py` 在隔离的临时索引上比较四档切片大小，重叠长度取切片大小的 17%，并用开发集 26 题检索。表中命中统计来自其中 19 道有标注页码的题；耗时是全部 26 题单次检索的平均值，包含本地 Ollama 问题向量生成。

| 切片长度 | 重叠长度 | 片段总数 | 前 3 条页码命中 | 平均检索耗时 |
| ---: | ---: | ---: | ---: | ---: |
| 200 | 34 | 2008 | 19/19 | 681.77 毫秒 |
| 350 | 60 | 1237 | 19/19 | 858.80 毫秒 |
| 500 | 85 | 947 | 16/19 | 703.53 毫秒 |
| 800 | 136 | 645 | 17/19 | 712.34 毫秒 |

350 与 200 在这批开发题上命中相同，350 的索引片段数少 771 个；500 和 800 的页码命中下降，因此首版采用 350。单轮耗时受模型服务负载影响，表中数据只反映这次本机运行。完整结果见 `evaluation/chunk-size-ablation.json`。


## 已知局限

- 手册和官网售后流程页提供车辆功能及公开流程信息；真实道路油耗、车型故障率、车主售后满意度和实际成交均价需要另行取得可核查的统计或交易数据。
- 26 道开发题对照检索结果编制并参与参数选择，其满分表现只代表开发集。25 道留出题未参与参数选择；目前缺少跨品牌、跨资料批次的外部测试集，以及对回答质量和抽取准确率的系统人工评估。
- 每份手册的索引覆盖安全警示、故障提示、保养和救援相关的部分页段，其余章节仍待纳入。留出集有两道目录/图片索引页题找到了同本文档的其他页，两道事实题没有召回；这四题均计为页码未命中。
- 相似度阈值和同页重复降权系数只在一小批开发题上校准过，更多车型和问法仍需验证。五道无资料题使用了当前明确识别的指标词，拒答率仅衡量这些问题。
- 引文校验目前只归一化空白字符，标点差异会导致误拒。后续可增加标点归一化或编辑距离容错；当前采用保守匹配，以减少误引。
